## 2. システム概要

### 2.1 背景

- 海外にしか流通していない商品(限定品・未発売品)に興味があっても、探す手段が限られている
- 既存の輸入代行・転送サービス(Buyee、malltail、Shipito等)は「購入後」の物流支援が中心であり、
「そもそも何がどこで買えるか」を発見する支援が手薄
- 海外通販の利用経験において、以下のような障壁が実際に確認されている
  - 検索キーワードが分からない(英語の壁)
  - 決済・関税の仕組みが分かりにくい
  - 商品ページを開くまで「日本への発送に対応しているか」が分からず、購入直前で離脱するケースがある(実体験:eBay利用時)
  - 検索結果に表示されるサイトの中には信頼性の低いもの(詐欺的なサイト)も混在しており、検索エンジンに表示されること自体が安全性を保証しない
    (実体験:某通販サイト「Oショップ」)

### 2.2 目的

自然言語による入力から、国内外の「現在購入できるサイト」および「過去の取引実績(オークション等)」への案内を横断的に提示することで、
越境ECにおける商品発見のハードルを下げる。

### 2.3 スコープ

**対象範囲**
- 商品名・特徴を自然言語で入力すると、関連する外部ECサイト・オークションサイトの検索結果URLを一覧表示する
- 決済方法・関税・用語解説などのヘルプコンテンツを提供する

**対象外(本サービスでは扱わない)**
- 商品の購入・決済処理そのもの(あくまで外部サイトへの案内に徹する)
- 商品データ(画像・詳細説明)の自社保存・複製
- 出品者情報や在庫状況など、外部サイトから詳細データを取得・自社表示する機能

### 2.4 想定ユーザー

- 海外限定品・未発売品に関心があるが、英語や海外通販の仕組みに不慣れな一般ユーザー
- 海外オークションでの過去の取引相場を知りたいユーザー

## 3. 要求獲得プロセス

REBOK(要求工学知識体系)の考え方に基づき、本要求がどのように獲得されたかを以下に整理する。

| 手法 | 内容 |
|---|---|
| 自己エスノグラフィ(実体験の洗い出し) | チームメンバー自身の海外通販利用経験(eBayでの発送非対応、詐欺サイトへの遭遇等)を要求の出発点とした |
| 既存サービス調査 | 輸入代行・転送サービス(Buyee等)を調査し、「発見」を支援する機能が手薄であることを課題として特定した |
| 有識者・指導教員へのヒアリング | ■要実施:ゼミでの発表・フィードバックを要求の妥当性確認に活用する |

## 4. 用語定義

| 用語 | 定義 |
|---|---|
| 現行販売サイト | 現在その商品を購入可能なECサイト(Amazon、eBay即決、Etsy等) |
| 過去のオークション履歴 | 落札済み(Sold)商品の情報が見られる検索結果ページ(eBay Sold、ヤフオク!等) |
| URLテンプレート方式 | 各サイトの検索URLの型にキーワードを差し込んでURLを自動生成する方式 |
| 意図判定 | ユーザー入力から「今すぐ購入したい」/「相場を知りたい」等の意図をLLMが推定する処理 |

## 5. 機能要件

優先度はMoSCoW法(Must:必須/Should:重要/Could:可能なら/Won't:今回対象外)で示す。

### FR-01 自然言語検索

- ユーザーはテキストボックスに自由記述で商品の特徴・名称を入力できる
- 入力例:「軽くて防水のトレッキングシューズ、海外限定モデル」
- **優先度**: Must
- **根拠**: 英語や専門的な検索キーワードが分からず、海外通販の利用に心理的ハードルを感じていた実体験に基づく(2.1)

### FR-02 意図判定・キーワード抽出

- LLM(Claude API等)を用いて、入力文から検索キーワードと意図(現行購入/相場確認/不明)を抽出する
- 意図が不明瞭な場合は両方の検索結果を提示する
- **優先度**: Must
- **根拠**: 「今すぐ買いたい」のか「相場を知りたい」のかで求める情報が異なるため、ユーザーの曖昧な入力から適切に振り分ける必要がある

### FR-03 現行販売サイトへの案内

- Web検索API(Google Custom Search API等)を用いて、抽出したキーワードで検索を行う
- 検索結果のうち、あらかじめ定めたECサイトドメインのリストに合致する結果を優先的に抽出する
- 商品名(検索結果のタイトル)・簡易説明・URLをカード形式で一覧表示する
- ■要確認: 対象とするECサイトのドメインリスト(国内外の主要ECを想定)を確定させる
- **優先度**: Must
- **根拠**: 国内外を横断して「今どこで買えるか」を一度に確認できるサービスが少ないという課題に基づく(2.1)

### FR-04 過去のオークション/相場サイトへの案内

- あらかじめ定義したオークション・フリマサイトの検索URLテンプレートに、キーワードを差し込んでURLを生成する
- 対象サイト例:ヤフオク!、eBay(Sold Listings絞り込み)、メルカリ
- 実データの取得・保存は行わない(URL生成のみ)
- **優先度**: Must
- **根拠**: 相場を知る手段が個別サイトの検索に限られており、横断的に確認できないという課題に基づく

### FR-05 検索結果の表示切り替え

- 「現行販売」タブと「過去の相場」タブを切り替えて表示できる
- 意図判定の結果に応じて、初期表示するタブを自動選択する
- **優先度**: Should
- **根拠**: FR-02の意図判定結果をユーザーに分かりやすく提示するために必要

### FR-06 為替換算の目安表示

- 為替レートAPIを用いて、表示価格(現地通貨)のおおよその円換算額を併記する
- 「送料・関税別、参考価格」である旨を明記する
- **優先度**: Should
- **根拠**: 現地通貨表示のみでは実質的な価格が分かりにくく、購入判断がしづらいという課題に基づく

### FR-07 ヘルプコンテンツ

- 以下の内容を静的コンテンツ(自作の解説文)として提供する
  - 決済方法の解説(クレジットカード、PayPal、Wise等)
  - 関税・消費税の仕組み
  - 頻出英単語辞典(Buy It Now、Bid 等)
  - 転送サービスの説明とリンク集
  - 怪しいサイトの見分け方(価格が相場より極端に安い、支払い方法が銀行振込のみ、不自然な日本語、ドメイン取得が新しい、会社情報が不明瞭、
    レビューが不自然、なりすましドメイン、SSLの過信に対する注意 等)
- **優先度**: Should
- **根拠**: 決済・関税の仕組みが分からず不安を感じた実体験、および詐欺サイトの見分け方を知らなかったために
            某通販サイト(Oショップ)に騙されかけ た実体験に基づく(2.1)

### FR-08 サイトの信頼性判定・表示

- 検索結果として表示する各サイトについて、外部の信頼性判定サービス(Google Safe Browsing API、ScamAdviser API等)から情報を取得し、バッジ形式で表示する
  - 例:「信頼スコア:82/100」「⚠️注意サイト」等
- 明らかに危険と判定されたサイト(フィッシング・マルウェア等)には強めの警告を表示する
- 口コミ・評判については、個別レビューの転載は行わず、Web検索結果をLLMが要約し「傾向」として自分たちの言葉で提示する
  (例:「配送の遅さを指摘する声が複数見られる」)
- **優先度**: Should
- **根拠**: 検索結果に表示されること自体が安全性の保証にならないという実体験(某通販サイト「Oショップ」等)に基づく(2.1)

## 6. 非機能要件

### NFR-01 権利遵守方針(最重要制約)

- 外部サイトのコンテンツ(画像・文章)は自社サーバーに保存・複製しない
- 外部サイトへは通常のハイパーリンクのみを用い、iframe等での埋め込みは行わない
- スクレイピングによるデータ取得は行わない。データ取得は公式API・検索API経由に限定する
- 商品説明を表示する場合は、検索結果を要約した自分たちの言葉で記述する(元文章の転載・翻訳表示は行わない)
- 非営利・学術目的での運用とする

### NFR-02 性能

- 検索結果は■要確認(目標:数秒以内)で表示されること

### NFR-03 可用性

- 卒論発表・デモ時に安定して動作すること(常時稼働は必須要件としない)

### NFR-04 セキュリティ

- APIキー等の秘匿情報はソースコードに直接記載せず、環境変数等で管理する

## 8. 前提条件

- ユーザーは日本語で入力することを基本とする
- 表示するリンク先の最終的な購入判断・手続きはユーザー自身が行う(本サービスは仲介・購入代行を行わない)

## 9. 妥当性確認(検証)方法

REBOKにおける要求の妥当性確認(Validation)に対応する項目。定義した要求が実際にユーザーの課題を解決するかを、以下の方法で検証する。

- **ユーザビリティテスト**: 被験者に商品検索タスクを行わせ、「発見できた商品数」「タスク完了時間」「満足度アンケート」を既存の検索方法
  (単純キーワード検索)と比較する
- **比較実験**: 「意図判定つき横断検索」と「単純キーワード検索」で、発見できる商品の質・多様性を比較する
- ■要実施: ゼミでの中間発表を通じて、指導教員・他ゼミ生からのフィードバックを要求内容の妥当性確認に用いる

## 10. 将来的な収益モデル(参考)

本サービスは卒業論文としては非営利・学術目的で実装するが、企画としての成立性を示すため、実運用を想定した収益モデルの案を以下に示す。

- **アフィリエイトプログラムの活用**: 本サービスは外部ECサイトへのリンク誘導を中核機能としており、各サイトが提供するアフィリエイトプログラム(Amazonアソシエイト、eBayパートナーネットワーク等)に参加することで、リンク経由の購入に対する成果報酬を得るモデルと親和性が高い
- **導入の容易さ**: 生成する案内URLにアフィリエイトタグを付与するだけで実装できるため、技術的な追加負担が小さい
- **既存の設計方針との整合性**: アフィリエイトリンクは各サイトが公式に許可した仕組みであり、これまでの「URLへの案内に徹する」という権利遵守方針と矛盾しない
- ■要検討: 広告掲載やフリーミアムモデル等、他の収益化手段についても比較検討の余地がある
